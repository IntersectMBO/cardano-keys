Description

Reading key files

Given a path, give me the key. Every function here takes a FilePath and nothing else: which files to read, which combinations of them are valid, and what to do with the result are the caller's business.

This is the only module in the package that touches the filesystem, so the boundary between the pure serialisation core and the code that opens files is visible at a glance. Nothing else here does IO.

Bulk credentials files

readBulkCredentialsFile :: FilePath -> IO (Either (FileError TextEnvelopeError) [(OperationalCertificate, SigningKey VrfKey, SigningKey KesKey)]) Source #

Read a bulk credentials file: the several sets of forging credentials a node can be given in one file.

The format is a JSON array of 3-element arrays, each element an inline text envelope: the operational certificate, the VRF signing key and the KES signing key, in that order.

This decodes and nothing more. In particular it does not check that each entry's operational certificate names its KES key — pass every entry through checkKesKeyMatchesOpCert before forging with it.

An entry that will not decode is reported against <file>.<index>cert, <file>.<index>vrf or <file>.<index>kes, because a bulk file with twenty pools and one bad envelope is otherwise very hard to debug.

Byron files

readByronSigningKeyFile :: FilePath -> IO (Either (FileError SerialiseAsRawBytesError) (SigningKey ByronKey)) Source #

Read a Byron signing key.

Not a text envelope: the file is the raw CBOR of a legacy Byron XPrv, and the node reads it as such rather than looking for a JSON wrapper.

The error is this package's SerialiseAsRawBytesError rather than a bare String, so that a caller can render it the same way as every other deserialisation failure.

readByronDelegationCertificateFile :: FilePath -> IO (Either (FileError Text) Certificate) Source #

Read a Byron delegation certificate.

Neither a text envelope nor CBOR: this file is canonical JSON, the same encoding as the Byron genesis, and this is the only place canonical-json is needed. The payload of a failure is the decoder's own message.
